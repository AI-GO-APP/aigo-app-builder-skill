# 新建 App 需求盤點表（Phase 1.5 §1.0 用）

> 本模板用於 `SKILL.md` Phase 1.5 §1.0，是**新建情景**的起手——對稱遷入線的
> `project_deconstruction_template.md`（那份盤既有系統的 stack，這份盤用戶腦中的需求）。
> 四問缺一不進產品線判斷；填不出來的格子＝還要再問用戶，不是留空。
> 一個需求填一份；判定要拆成多個 app 時，「app 分配表」每個 app 一列。

## 一、誰在用（→ access_mode，不可逆）

| 問題 | 用戶的回答 |
|------|-----------|
| 登入的是租戶內部成員、外部客戶／會員／公眾、還是兩者都有？ | |
| 內部成員中有沒有**沒有 `builder.access` 的一般員工**？（決定自建表存取要不要包 Server Action，規則 31） | |
| 有沒有「不登入也要能看」的頁面？哪幾頁？ | |

結論：`internal` / `external` / 兩者都有（→ 拆成兩個 app）

- 功能群 ≥ 2 且目的不同（例：客戶管理 vs 財務報表）→ 第 2 項拆分

  還是租戶自有的新實體（→ 自建表）

## 三、對外面向

| 問題 | 用戶的回答 |
|------|-----------|
| 需要自有網域嗎？ | |
| 需要 SEO／社群分享卡嗎？ | |

結論：應用介面 / 公開 web 資產 / 混合（→ 拆：公開站 Hosted、後台 Custom）
